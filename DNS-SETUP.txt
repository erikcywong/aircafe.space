# aircafe.space — DNS 配置与故障诊断
# 更新时间：2026-10-08（修正 2026-10-07 版本的关键误判）
#
# ============================================================================
# 结论：根因是「名称伺服器（NS）指错了」，不是 GitHub 侧问题，也不是证书问题。
# ============================================================================
#
# 2026-10-08 实测（Google DNS 8.8.8.8 + Cloudflare 1.1.1.1 双解析器一致）：
#   aircafe.space        apex A  → 无任何记录（NOERROR，空应答）
#   www.aircafe.space    A      → NXDOMAIN（Status 3，该名字不存在）
#   CNAME / TXT / CAA           → 全部无
#   权威 SOA            → NS1.DOMAIN.COM  dnsadmin.DOMAIN.COM  serial = 1（空 zone）
#
# 根因对比（RDAP 证实两个域名注册商同为 Alibaba Cloud / 万网 HiChina）：
#   ✅ fec-coffee.space   NS = dns19/dns20.hichina.com   ← 正确（阿里云 DNS）
#   ✅ regal-coffee.space NS = dns31/dns32.hichina.com   ← 正确
#   ✅ kuok-coffee.space  NS = dns27/dns28.hichina.com   ← 正确
#   ✅ napell.life        NS = dns25/dns26.hichina.com   ← 正确
#   ❌ aircafe.space      NS = ns1.domain.com / ns2.domain.com  ← 错误！停留在停放 DNS
#
#   => 全球解析器问的是 domain.com 的服务器。因此在阿里云「云解析 DNS」里添加的任何
#      记录都不会生效——记录加对了地方，但那个地方没人问。这是全部故障的唯一原因。
#
# 域名本身健康：注册商 Alibaba Cloud (HiChina)，到期 2027-01-24，
# 状态 clientTransferProhibited（正常锁，非异常）。续费 / 注册均无问题。
#
# GitHub 侧完全正常（无需改动）：
#   status=built | source=main / | cname=www.aircafe.space | repo CNAME=www.aircafe.space
#   https_enforced=false | certificate_state=none（因域名不解析，无法签发证书）
#
# ⚠ 副作用：仓库 CNAME 为 www.aircafe.space，GitHub Pages 会把
#   https://erikcywong.github.io/aircafe.space/ 也 301 到 http://www.aircafe.space/
#   → 即 NXDOMAIN。所以「备用 github.io 链接」目前同样是打不开的。
#
# ────────────────────────────────────────────────────────────────────────────
# 修复步骤（必须由你在阿里云控制台操作，本机无注册商 API 连接器）
# ────────────────────────────────────────────────────────────────────────────
#
# 【第 1 步 · 关键】把 NS 切到阿里云
#   阿里云控制台 → 域名 → aircafe.space → 「DNS 修改」（修改 DNS 服务器）
#   → 选择「阿里云 DNS」（自动分配 dnsXX.hichina.com 一对，形如 dns29/dns30）
#   → 保存。此步不做，第 2 步的记录永远不生效。
#   注意：注册商处的 NS 变更通常 1–24 小时全球传播（.space 一般几小时内）。
#
# 【第 2 步】在阿里云云解析 DNS 添加记录
#   云解析 DNS → aircafe.space → 解析设置 → 添加记录：
#
#     TYPE    NAME     VALUE / TARGET
#     A       @        185.199.108.153
#     A       @        185.199.109.153
#     A       @        185.199.110.153
#     A       @        185.199.111.153
#     CNAME   www      erikcywong.github.io
#
#   可选（IPv6，GitHub 官方地址）：
#     AAAA    @        2606:50c0:8000::153
#     AAAA    @        2606:50c0:8001::153
#     AAAA    @        2606:50c0:8002::153
#     AAAA    @        2606:50c0:8003::153
#
#   填表要点：
#   - 阿里云「记录类型」直接选 A / CNAME；@ 表示根域
#   - CNAME 值只填主机名 erikcywong.github.io，不要 https:// 前缀，不要末尾加点
#   - TTL 默认（10 分钟或 3600）即可
#   - 不要用 ALIAS/ANAME 把根域指向 github.io（GitHub 不支持）
#   - 这一步与 fec / regal / kuok / napell.life 完全一致，可直接复制现成记录
#
# 【第 3 步】验证（NS 生效后再查）
#     nslookup -type=ns aircafe.space 8.8.8.8
#       → 应返回 dnsXX.hichina.com，而不是 ns1.domain.com
#     nslookup aircafe.space 8.8.8.8
#       → 应返回 185.199.108–111.153 四个 IP
#     nslookup www.aircafe.space 8.8.8.8
#       → canonical name = erikcywong.github.io
#
# 【第 4 步】开启 HTTPS 强制
#   解析生效后 GitHub 自动签发 Let's Encrypt 证书（几分钟到 1 小时）。
#   然后调用 API 打开 Enforce HTTPS：
#     PATCH https://api.github.com/repos/erikcywong/aircafe.space/pages
#     body: {"https_enforced": true}
#
# ────────────────────────────────────────────────────────────────────────────
# 域名生效前想立即看到站点？
# ────────────────────────────────────────────────────────────────────────────
# 由于仓库 CNAME 文件指向 www.aircafe.space，github.io 备用链接也被 301 到死域名。
# 若要立即恢复访问，需临时从仓库移除 CNAME 文件（可随时加回）。
